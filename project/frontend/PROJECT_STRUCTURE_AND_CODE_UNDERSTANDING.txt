B.5 src/router/index.ts  —— 「模块跳转方式」的核心
------------------------------------------------------------------
职责：集中定义 SPA 所有路由、路由级别的权限控制、页面切换时的滚动控制

【路由表】
  path                 name         component                               meta
  '/'                  home         HomeView.vue                              —
  '/cart'              cart         CartView.vue                              —
  '/favorites'         favorites    FavoritesView.vue                         —
  '/products'          allProducts  AllProductsView.vue                       —
  '/checkout'          checkout     CheckoutView.vue                          requiresAuth: true
  '/product/:id'       product      product/ProductDetailView.vue              —
  '/category/:cat'     category     category/CategoryView.vue  props:true     —
  '/login'             login        LoginView.vue                             noAuth: true
  '/register'          register     RegisterView.vue                          noAuth: true
  '/profile'           profile      ProfileView.vue                           requiresAuth: true

【路由守卫 beforeEach】（决定"能不能跳 / 跳去那里"）
  - 要跳的路由 meta.requiresAuth=true 且 isLoggedIn=false
      → return { path: '/login', query: { redirect: to.fullPath } }
        （登录后 LoginView.vue 会读 query.redirect 还原到原目标，而不是一律跳 profile）
  - 要跳的路由 meta.noAuth=true 且 isLoggedIn=true（已登录却打开登录/注册）
      → return { path: '/profile' }
        避免重复登录/注册

【scrollBehavior】(决定"跳过去后滚动条停在哪")
  - savedPosition 存在（浏览器 ←/→ 前进后退）→ 返回 savedPosition，用户滚动位置保持不变
  - 其他情况（点击Logo / 按钮 / router.push）→ 返回 {top:0, behavior:'smooth'}
    修复从商品详情(>2000px高度)滚到底部再回首页看到的"空白"（实际是停在 y=2000+）的问题

【模块跳转方式】
  全工程所有跳转都统一用 Vue Router 的两种方式：
    1) SFC 脚本：import { useRouter } from 'vue-router'
                const router = useRouter()
                router.push('/products')
                router.push({ path: '/profile', query: { tab: 'addresses' } })
       常用入口：HomeView "查看全部" → /products；Checkout 无地址 → /profile?tab=addresses；…
    2) 用户点击浏览器 ←/→：由 scrollBehavior savedPosition 还原

B.6 src/components/HeaderNav.vue  ——  全局导航（所有页面共享的跳转枢纽）

------------------------------------------------------------------
B.7 src/stores/  状态管理层（所有业务数据的 Single Source of Truth）
------------------------------------------------------------------
每个文件都符合统一模式：
  interface DataType → const STORAGE_KEY → load() 读 localStorage → reactive state → save()
  → 导出 useXxx() 返回 state 供视图引用；导出具体 action 函数（toggle/add/remove/...）
  → 导出 computed 做筛选/汇总。

下面逐个文件说明：

B.7.1 user.ts — 用户
  接口：User {username, password, createdAt}
        CurrentUser {username, loginAt}
  持久化：shop_users（已注册账号列表） + shop_current_user（当前登录）
  导出：
    isLoggedIn = computed(state.current !== null)  —— 路由守卫用；ProfileView / Checkout 登录态判定
    currentUsername = computed(当前用户名 or '')   —— HeaderNav 头像名；订单默认地址收货人
    register(username,password) → 校验：长度 + 去重 → 写 shop_users
    login(username,password)    → 比对 shop_users → 写 shop_current_user
    logout()                    → 清掉 shop_current_user
  谁依赖：router/index.ts、HeaderNav、LoginView、RegisterView、ProfileView、stores/addresses.ts

B.7.2 cart.ts — 购物车
  接口：CartItem { id,name,desc?,price,originalPrice?,emoji,bgColor,quantity,selected,promotions? }
  持久化：shop_cart；load() 时自动给老数据补 selected=true 默认
  响应式 state：{items: CartItem[]}
  核心 action：
    addToCart(item, qty=1)   ——  存在则数量加 qty，不存在 push 默认 selected=true
    removeFromCart(id)       —— 单项删
    removeFromCartBatch(ids) —— 批量删
    updateQuantity(id, qty)  —— qty≤0 自动删
    toggleSelected(id)       —— 单行 checkbox 切换
    selectAll(checked)       —— 顶部全选
    moveToFavorites(ids)     —— 不删，仅返回 items 子集（用户要求移入后仍保留购物车）
    clearCart()              —— 创建订单 createOrder 后调用，清空结算完毕的购物车
  computed（视图直接渲染）：
    selectedItems  勾选中的商品（结算用）
    selectedTotal  选中商品金额合计（Checkout 费用明细）
    isAllSelected  列表顶部全选 checkbox 的 checked 值
  谁依赖：HeaderNav（购物车角标）、HomeView/CategoryView/ProductDetailView/AllProductsView（加购）、
          CartView、ProfileView（购物车 Tab）、stores/orders.ts createOrder

B.7.3 favorites.ts — 收藏夹
  接口：FavoriteItem { id,name,price,emoji,bgColor,addedAt }
  持久化：shop_favorites
  action：
    isFavorite(id): boolean              商品详情 ❤️ 按钮状态
    addToFavorite(item)                  去重后 push
    removeFromFavorite(id)               FavoritesView / ProfileView 单项取消
    toggleFavorite(item)                 ❤️ 切换
  computed：通过 useFavorites().items 渲染
  谁依赖：HeaderNav 角标、FavoritesView、ProductDetailView 收藏按钮、ProfileView 收藏夹 Tab、
          CartView（批量移入收藏 -> addToFavorite）

B.7.4 history.ts — 浏览历史
  接口：HistoryItem {id,name,emoji,bgColor,viewedAt}
  持久化：shop_history；上限 50 条
  action：
    recordView(omit viewedAt)   —— 先去重 splice，再 unshift 顶掉最老超出的 50 条以外；save
                                  调用点：HomeView/CategoryView/AllProductsView/CartView 推荐区/ProfileView 不调
                                  只有 ProductDetailView goDetail() 才会 recordView
    clearHistory()              —— ProfileView 浏览历史 Tab "清空历史"按钮
  谁依赖：ProductDetailView（写）、ProfileView（渲染；整行点击跳 /product/:id）

B.7.5 shops.ts — 关注店铺
  接口：Shop { id,name,logo,bgColor,followers,rating,followedAt? }
  数据策略：店铺列表（defaultShops 6 个 Demo 店铺）固定写死，不按 id 增长
            用户关注存在 shop_followed_shops，只存 id 列表，不存整 Shop
  响应式 state：{all: Shop[], followedIds: number[]}
  核心：
    followedShops = computed( 从 all 里按 followedIds 过滤出已关注的 Shop[] )
    isFollowed(shopId)/followShop/unfollowShop/toggleFollow
  谁依赖：ProfileView（🏪 关注店铺 Tab 展示 followedShops；未关注按钮显示 "关注"/"已关注"）
          ProductDetailView 店铺条：商品 → SHOPS[product.category] 对应店铺；显示关注按钮

B.7.6 reviews.ts — 评价管理
  接口：Review { id,productId,productName,productEmoji,productBgColor,orderId?,rating,content,createdAt }
  持久化：shop_reviews
  工具：genReviewId → 'r_' + 36进制时间 + 随机码（毫秒级重复避免）
  action：
    addReview(Omit id+createdAt)   —— 订单 Tab「评价」弹窗确认后 / ProfileView + Demo
    updateReview(id, {rating?,content?})   —— 改评价（预留）
    deleteReview(id)                        —— 单项删
    hasReviewed(productId)                  —— 订单 Tab「⭐去评价/已评价」状态
  谁依赖：ProfileView ⭐评价管理 Tab、订单 Tab 每个完成订单的"评价"按钮
          ProductDetailView 评价列表：所有 list.filter productId 匹配的 Review[]

B.7.7 coupons.ts — 优惠券
  类型：
    CouponScope = 'all'/'digital'/'fashion'/'homegoods'/'newuser'
    scopeLabel（中文名）/ scopeColor（主题色）  —— ProfileView Tab / 券卡片 渲染
    Coupon { id,title,value,threshold,scope,desc?,claimedAt,startAt,endAt,usedAt? }
  持久化：shop_coupons
  computed（最核心的 3 个分组）：
    availableCoupons = 未使用 且 startAt ≤ now ≤ endAt   （可用券 Tab）
    usedCoupons      = usedAt 有值                       （已使用 Tab）
    expiredCoupons   = 未使用 且 endAt < now              （已过期 Tab）
  action：
    claimCoupon({…, durationDays?, startDelayHours?})  —— 领一张券（时间自动算）
    useCoupon(id)        —— 核销（预留）；已用/过期 false
    removeCoupon(id)     —— 券卡片上的删除按钮
    formatCouponDate(ts) —— YYYY.MM.DD，用于卡片有效期
    remainingDays(endAt) —— 还有几天到期；≤3 天显示红色警告
    ensureInitCoupons()  —— ProfileView 初始化调；若 0 条则塞 5 张 Demo（可用3/过期1/已用1）
  谁依赖：ProfileView 🎟️ 优惠券 Tab（三个子 Tab 用三个 computed）、

B.7.8 addresses.ts — 收货地址（按用户隔离！）
  接口：Address { id,name,phone,region,detail,isDefault,createdAt,updatedAt }
  持久化：shop_addresses → Record<username, Address[]>（按用户名隔离，多账号不冲突）
  响应式 state：{ list: Address[] }
    重载逻辑 reloadCurrentUser()：watch [currentUsername, isLoggedIn] 变化，
    根据当前登录用户把地址从 DB 读并排序列出（默认在前、updatedAt 倒序），未登录返回 []
  核心 action：
    addAddress({name, phone, region, detail, isDefault?})   —— 校验 + 默认地址处理（首条自动默认；
                                                              isDefault=true 时先把其他地址取消默认）
    updateAddress(id, partial)                               —— 同 addAddress 处理默认唯一性
    deleteAddress(id)                                         —— 若删的是默认且还有其他地址，剩余第 1 条自动升默认
    setDefaultAddress(id)                                     —— 全用户只允许 1 个 true
    内置 validate()：姓名 20/手机号^1[3-9]\d{9}$/省市区非空/详细地址 120 字
    defaultAddress = computed()（默认地址 或 第 1 条 或 null）
  谁依赖：
    ProfileView 📍 地址管理 Tab — 列表 + 增/改/删 + 设默认
    CheckoutView 地址模块      — 取默认地址 或 用户在弹窗选择的地址（selectedAddressId）、新建地址调 addAddress

B.7.9 orders.ts — 订单（订单状态机 + 时间戳/物流/退款生成）
  类型：
    OrderItem { id,name,price,emoji,quantity }
    OrderStatus = 'pending' | 'paid' | 'shipped' | 'done' | 'cancelled' | 'refunding' | 'refunded'
    LogisticsNode {time,status,isNew?}
    InvoiceInfo {type,title,taxNo?,content,issued}
    RefundInfo {appliedAt,reason,amount,status:'审核中'|'已同意'|'已拒绝'}
    Order { id,items,totalAmount,status,createdAt, [paidAt|shippedAt|doneAt|cancelledAt]?, logistics?, remark?, invoice?, refund?, payMethod? }
  持久化：shop_orders
  工具：genOrderId → YYYYMMDDhhmmss + 4 位随机；fmt() 时间格式化；buildLogistics(status) 生成 Mock 物流
  核心 action：
    createOrder(cartItems, {remark?, invoice?})   —— CartView 去结算 / 详情立即购买调用
                                                    生成 pending 订单 + 调用 clearCart()
    updateOrderStatus(orderId, status, {payMethod?})
         —— 状态机核心：
             → paid：写 paidAt+payMethod+初始物流（"等待商家发货"）；setTimeout 2000 自动变成 shipped
             → shipped：写 shippedAt+完整 3 段物流（转运/分拨/派送）
             → done：写 doneAt
             → cancelled：写 cancelledAt
    cancelOrder(orderId) —— 仅 pending 可以；ProfileView 订单 Tab 取消按钮
    setOrderRemark(orderId, text) —— 订单备注
    applyRefund(orderId, reason)
         —— paid/shipped/done 才能申请 → refunding → setTimeout 2s → refunded
    copyOrderId(orderId) —— 剪贴板：优先 navigator.clipboard，不支持时 textarea + execCommand
  谁依赖：
    CartView、ProductDetailView（createOrder → /checkout）
    CheckoutView（updateOrderStatus → paid / cancelled）
    ProfileView 我的订单 Tab（订单列表、状态显示、操作按钮、退款/备注/复制/物流弹窗）

B.9 src/api/  后端接口层（★ 已预埋完成，当前默认不启用）
------------------------------------------------------------------
【设计原则：现在"不连后端"是怎么保证的？】
  - 总开关 src/api/config.ts 里 USE_BACKEND = false，
    request() 函数第一行就拦截并抛 ApiError("后端未开启")，
    全程不会发出任何网络请求。
  - 所有 stores 依旧读写 localStorage，所有页面行为与之前完全一样。
  - 换句话说：api/ 是一条"预埋好的管线"，铺好了但没通水。

【与 stores 的关系】
  - stores/*.ts   = 现在的数据源（localStorage，唯一在被使用的）
  - api/*.ts      = 将来的数据源（HTTP 请求，备而未用）
  - 两者接口刻意对齐（ApiXxx 类型字段与 store 里同名 interface 一致），
    迁移时视图层几乎不用改字段名。

【文件分类速览：2 个基础设施 + 7 个业务接口】
  一、基础设施（所有请求的底层支撑）
    config.ts    全局开关 + 配置（连不连后端只看这一个文件）
    request.ts   HTTP 请求封装（拼 URL/注 token/超时/解包响应/统一错误）
  二、业务接口（每个对应一个 store，函数统一 apiXxx 前缀）
    user.ts      ← stores/user.ts      注册/登录(自动存token)/登出/个人信息
    product.ts   ← stores/products.ts  商品列表(分类/搜索/分页)/商品详情
    cart.ts      ← stores/cart.ts      购物车查/加/改数量/选中/批量删/清空
    order.ts     ← stores/orders.ts    订单创建/查询/支付/取消/退款/备注
    favorite.ts  ← stores/favorites.ts 收藏查/加/取消
    address.ts   ← stores/addresses.ts 地址查/增/改/删/设默认
    coupon.ts    ← stores/coupons.ts   优惠券列表分组(可用/已用/过期)/领取/核销
  注：浏览历史/关注店铺/评价 3 个模块暂未预埋，需要时按同样模式补充即可。

【调用链（将来启用后端时）】
  View 页面 → stores/*.ts → api/*.ts → request.ts → fetch → 后端
                          ↑               ↑
                   字段类型对齐      统一拼 URL/加 token/超时/错误处理

B.9.1 config.ts —— 全局配置 / 唯一开关（连不连后端只看这一个文件）
  USE_BACKEND      false = 纯前端 localStorage 模式（现在）；true = 真实后端模式
  API_BASE_URL     后端地址，如 'http://localhost:8000'；走 vite 代理时改为 ''
  API_PREFIX       统一路由前缀 '/api'
  REQUEST_TIMEOUT  超时 10 秒（AbortController 自动中止）
  TOKEN_KEY        登录 token 的 localStorage 键（'shop_token'）

B.9.2 request.ts —— HTTP 请求封装（原生 fetch 实现，不引入 axios，零新依赖）
  导出：
    ApiError 类                       统一错误（code 业务码 / status HTTP 码 / message 提示）
    getToken() / setToken() / clearToken()   token 三件套
    request(method, url, body?, params?)     所有业务接口的唯一出口
  request() 内部流程：
    ① USE_BACKEND=false → 直接抛"后端未开启"（不发请求）
    ② 拼 URL：API_BASE_URL + API_PREFIX + url + querystring（undefined 参数自动过滤）
    ③ 请求头：Content-Type: application/json + Authorization: Bearer <token>（有 token 才带）
    ④ AbortController 10 秒超时
    ⑤ 响应约定 { code, message, data }：code===0 → 返回 data；否则抛 ApiError(message)
    ⑥ HTTP 401 → clearToken() + 抛"登录已过期"（将来可在此跳 /login）
    ⑦ 网络异常/超时 → 包装成友好文案的 ApiError
  后端响应格式约定（所有接口统一）：
    成功 { "code": 0, "message": "ok", "data": ... }
    失败 { "code": 非0, "message": "错误提示", "data": null }

B.9.3 业务接口文件（每个文件 = 对应 store 的"远程版"，函数统一 apiXxx 前缀）
  user.ts      apiRegister / apiLogin(成功自动 setToken) / apiLogout(自动 clearToken) / apiGetProfile
  product.ts   apiGetProductList({category?, keyword?, page?, pageSize?}) / apiGetProductDetail(id)
  cart.ts      apiGetCart / apiAddToCart(item, qty) / apiUpdateCartQuantity / apiToggleCartSelected
               / apiSelectAllCart / apiRemoveCartItems(ids[]) / apiClearCart
  order.ts     apiCreateOrder(items, {remark?}) / apiGetOrderList(status?) / apiGetOrderDetail
               / apiPayOrder(id, payMethod) / apiCancelOrder / apiApplyRefund(id, reason)
               / apiUpdateOrderRemark
  favorite.ts  apiGetFavorites / apiAddFavorite / apiRemoveFavorite
  address.ts   apiGetAddressList / apiCreateAddress / apiUpdateAddress(id, partial)
               / apiDeleteAddress / apiSetDefaultAddress
  coupon.ts    apiGetCoupons('available'|'used'|'expired'?) / apiClaimCoupon / apiUseCoupon(id, orderId?)
  注：浏览历史 / 关注店铺 / 评价 3 个模块暂未预埋，需要时按同样模式
      （"新建 api/xxx.ts + request() + apiXxx 函数 + 注释写清 store 对照"）补充即可。

【将来启用后端只需 3 步】
  ① src/api/config.ts     → USE_BACKEND 改 true；API_BASE_URL 填后端地址（配合代理则改 ''）
  ② vite.config.ts        → 解开 server.proxy 注释，target 填后端地址（解决浏览器跨域）
  ③ 按 B.9.4 对照表逐模块把 store 里的 localStorage 逻辑替换为 api 调用
    （替换哪个模块哪个模块生效，未替换的继续走本地，可以渐进式迁移）

B.9.4 store → api 迁移对照表（联调时照着改）

  stores/products.ts  getProductById / getProductsByCategory / allProducts

【常见问题与修复记录】

2026-09-05  vite.config.ts 里 import { fileURLToPath, URL } from 'node:url' 画红线
    原因：项目缺少 @types/node（Node.js 的 TypeScript 类型声明包），TS 不认识
           node:url / URL / fileURLToPath 等 Node 内置 API
    修复：① npm install -D @types/node（v26.4.1）
          ② tsconfig.node.json 的 compilerOptions 里加 "types": ["node"]
             （该配置文件只管 vite.config.ts，必须显式声明加载 node 类型）
    验证：npx tsc -p tsconfig.node.json --noEmit → exit=0 通过
    注意：此红线只是编辑器类型提示，不影响 npm run dev 运行
           （Vite 用 esbuild 编译，不依赖这个类型检查）
    IDE 刷新：若装完包红线仍在，Ctrl+Shift+P → "TypeScript: Restart TS Server"
